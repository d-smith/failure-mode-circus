## 2026-08-06 — Step 1: `/calc` handler

Added to `services/reference-service/main.go`:
- `calcResponse` (op1, op2, operator, result — all JSON-tagged) and
  `errorResponse` (error) types.
- `writeJSONError(w, status, msg)` helper — sets `Content-Type:
  application/json`, writes the status, encodes `errorResponse`.
- `calcHandler(w, r)`: rejects non-GET with 405; parses `op1`/`op2` query
  params via `strconv.ParseFloat` (400 on failure — covers non-numeric and
  missing params, since an empty string also fails to parse); switches on
  `operator` (`add`/`sub`/`mul`/`div`, 400 on unknown value); for `div`,
  checks `op2 == 0` before dividing and returns 400 with an error message
  containing "division by zero"; success returns 200 JSON.
- Registered `/calc` on the mux in `main()` alongside `/healthz`.

Deviation from plan wording: error message text landed as "op1 and op2 must
be numeric" / "operator must be one of add, sub, mul, div" / "division by
zero" / "method not allowed" — matches the plan's intent, exact wording is
implementation-owned and not repeated verbatim from the plan doc.

Also added (originally scoped to step 3, but user asked for runnable unit
tests before checking off step 1, so pulled forward for just the `/calc`
handler): `TestCalcHandlerSuccess` (table-driven over add/sub/mul/div),

## 2026-08-06 — Step 2: `healthcheck` self-check subcommand

Added to `services/reference-service/main.go`:
- `runHealthcheck(addr string) int`: parses the port out of `addr` via
  `net.SplitHostPort` (falls back to `"8080"` if that fails or the port
  comes back empty); does a GET to `http://127.0.0.1:<port>/healthz` with a
  2-second-timeout `http.Client`; returns `1` on any request error or a
  non-200 response, `0` otherwise.
- `main()` now checks `os.Args[1] == "healthcheck"` (guarded by
  `len(os.Args) > 1`) before starting the server, and if set calls
  `os.Exit(runHealthcheck(addr))` — this is the entry point ECS's
  `["CMD", "/reference-service", "healthcheck"]` container health check
  will invoke once wired up in Terraform (step 6-8).
- New imports: `fmt`, `net`, `time`.

Also added tests (pulled forward from step 3, same reasoning as step 1) in
`services/reference-service/main_test.go`: `TestRunHealthcheckSuccess`
(spins an `httptest.NewServer` wrapping a `/healthz`-only mux, asserts
`runHealthcheck` returns 0 against it) and `TestRunHealthcheckFailure`
(reserves a free `127.0.0.1` port then immediately closes the listener so
nothing answers, asserts `runHealthcheck` returns 1). New import: `net`.
User ran `go test ./... -v` locally and confirmed all tests pass before
this step was checked off.

## 2026-08-06 — Step 6: `ecs-service` module `health_check` input

Added an optional `health_check` field to each entry of the `containers`
object-list variable in `terraform/modules/ecs-service/variables.tf`
(same `optional(...)` style already used for `command`/`cpu`/etc.):
```hcl
health_check = optional(object({
  command      = list(string)
  interval     = optional(number, 15)
  timeout      = optional(number, 5)
  retries      = optional(number, 3)
  start_period = optional(number, 10)
}), null)
```
Defaults to `null` overall, so existing container entries without a
`health_check` block are unaffected. `command` is required when the block
is set (no sensible default); interval/timeout/retries/start_period default
to 15s/5s/3/10s per the plan's demo-friendly timing rationale. User
reviewed and confirmed. No wiring into `main.tf`'s `container_definitions`
yet — that's step 7.

## 2026-08-06 — Step 7: wire `health_check` into `container_definitions`

the `container_definitions` local, right after `portMappings`:
```hcl
healthCheck = c.health_check == null ? null : {
  command     = c.health_check.command
  interval    = c.health_check.interval
  timeout     = c.health_check.timeout
  retries     = c.health_check.retries
```

## 2026-08-06 — Step 9: k6 `smoke.js` rewritten for `/calc`

Rewrote `k6/scripts/reference-service/smoke.js`: added `OPERATORS =
['add','sub','mul','div']`, a `randomInt(max)` helper, and an
`expectedResult(op1, op2, operator)` helper mirroring the service's own

`/calc` call already proves the service is up. `options` (3 VUs, 30s,
`http_req_duration p(95)<500`, `checks rate>0.99`) unchanged. User reviewed
and confirmed.
