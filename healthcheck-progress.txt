## 2026-08-06 — Step 1: `/calc` handler

Added to `services/reference-service/main.go`:
- `calcResponse` (op1, op2, operator, result — all JSON-tagged) and
  `errorResponse` (error) types.
- `writeJSONError(w, status, msg)` helper — sets `Content-Type:
  application/json`, writes the status, encodes `errorResponse`.
- `calcHandler(w, r)`: rejects non-GET with 405; parses `op1`/`op2` query
  params via `strconv.ParseFloat` (400 on failure — covers non-numeric and
  missing params, since an empty string also fails to parse); switches on
  `operator` (`add`/`sub`/`mul`/`div`, 400 on unknown value); for `div`,
  checks `op2 == 0` before dividing and returns 400 with an error message
  containing "division by zero"; success returns 200 JSON.
- Registered `/calc` on the mux in `main()` alongside `/healthz`.

Deviation from plan wording: error message text landed as "op1 and op2 must
be numeric" / "operator must be one of add, sub, mul, div" / "division by
zero" / "method not allowed" — matches the plan's intent, exact wording is
implementation-owned and not repeated verbatim from the plan doc.

Also added (originally scoped to step 3, but user asked for runnable unit
tests before checking off step 1, so pulled forward for just the `/calc`
handler): `TestCalcHandlerSuccess` (table-driven over add/sub/mul/div),
`TestCalcHandlerDivideByZero`, `TestCalcHandlerInvalidOperator`,
`TestCalcHandlerInvalidOperands` (non-numeric op1, non-numeric op2, missing
op1, missing op2), `TestCalcHandlerMethodNotAllowed` — all in
`services/reference-service/main_test.go`, following the existing
`httptest.NewRequest`/`httptest.NewRecorder` direct-handler-call pattern.
User ran these locally and confirmed passing before this step was checked
off.
